## Section 1: 你每篇文章，有多少时间是在"调样式"上

- **论点**: 排版不是内容，却吃掉你大量创作时间。平均 45 分钟里，70% 在调 Markdown Nice 的样式——每次发文章都要从头来一遍。
- **引用的 atoms**: atom: claim-01, evidence-data-01
- **关键细节**:
  - 用"你是不是也遇到过"的 SCQA 结构开头
  - 场景：打开 Markdown Nice → 调字号颜色 → 粘贴 → 发现间距歪了 → 再调 → 重新粘贴
  - 冲突：45 分钟时间里这些事跟你的内容质量毫无关系
  - 答案预告：有个工具把"选风格 → 一键复制"这件事变成了 30 秒
  - 避免：不说"微信编辑器剥离 class 属性"这类技术原因，只说"粘贴后样式会乱"
- **预估字数**: 150
- **视觉断点**: 金句卡 — "排版不是内容，却吃掉你 30% 的创作时间。"
- **depends_on_previous**: false
- **writer 注意**: 第二人称"你"到底，不用"创作者"；禁止开头先定义工具是什么；以冲突场景开篇

## Section 2: 跟 AI 说"我要科技感强一点"，主题就做好了

- **论点**: LLM 大爆发改变了工具的可用门槛。wechat-typeset 内置 AI 接口，你用自然语言描述想要的风格，AI 直接帮你生成专属主题——不需要懂 CSS，不需要学 TypeScript，描述词汇就是你的设计输入。
- **引用的 atoms**: atom: claim-02, action-03
- **关键细节**:
  - 核心流程（面向用户视角，非技术）：你说"科技感、深色背景、代码块要有终端风" → AI 理解 + 生成 → 工具自动验证样式是否符合微信规范 → 不符合的地方 AI 自己改 → 直到通过
  - 强调：用户不需要知道工具在校验什么规则，那是工具自己的事
  - 对比一句话：壹伴的 AI 帮你"写文字"，wechat-typeset 的 AI 帮你"做主题"——两件完全不同的事
  - 如果在用 Claude Code / InkFlow：写作 pipeline 里会自动帮你完成排版，这一步不需要手动操作
- **预估字数**: 250
- **视觉断点**: 流程卡（3 步）— "描述风格 → AI 生成 → 一键使用"，不放代码，放人话步骤

## Section 3: 9 种"文章人格"——换掉的不只是颜色

- **论点**: 大多数排版工具的"主题"不过是换个配色。wechat-typeset 的每套主题是一套完整的视觉身份——字距、装饰元素、提示块样式、分隔线风格全部联动变化。财经稿、技术教程、生活随笔，视觉气质完全不同。
- **引用的 atoms**: atom: claim-04, analogy-01, evidence-data-05
- **关键细节**:
  - 用衣服类比（analogy-01）：同一个人穿正装、运动服、汉服——不只是换颜色，是整体气质不同
  - 9 套主题名称（用中文场景描述，不用英文 slug）：科技极客、财经商务、文学人文、行业观察、生活美学……每套对应一类内容气质
  - 栏目绑定主题的概念：你的技术文章固定用一套，生活分享用另一套，读者一看排版就知道这是哪类内容
  - 容器扩展语法（用户视角）：工具支持步骤卡、金句卡、对比块等 20 多种"内容组件"，选定主题后这些组件自动套用对应风格
  - 避免：不讲 SVG motif AST、不讲 token，讲"视觉效果上的区别"
- **预估字数**: 300
- **视觉断点**: 主题效果对比图（illustrator 产出）— 同一段文字用"tech-geek"和"life-aesthetic"两套主题渲染，直观看差异
- **时效敏感项**: 主题数量 9 套，发布前确认
- **depends_on_previous**: false（可单独阅读）
- **writer 注意**: 用读者能感知的词——"字间距更松"、"有边框的提示块"、"分隔线变成了小花纹"；禁止出现"PersonaSpec 有 11 个 hex token"

## Section 4: 粘贴进去，样式永远不会"塌"

- **论点**: 公众号排版最让人崩溃的不是调样式，是"调完了粘贴进去又塌了"。wechat-typeset 把这个问题从根上解决：工具的预览窗口和你最终粘贴到公众号的效果是同一个东西，没有误差。
- **引用的 atoms**: atom: claim-05, case-03
- **关键细节**:
  - 用对比讲清楚问题：其他工具的预览是"大概这样"，wechat-typeset 的预览是"就是这样"
  - 375px 预览窗宽度 = 手机屏幕宽度，你看到的就是读者在手机上看到的
  - 案例（case-03，非技术化描述）：曾经遇到手机竖排变错位的问题，这类坑工具内部已经自动处理掉了，用户不需要知道是怎么处理的
  - 数据安全加分项（顺带一提）：全本地运行，草稿不上传服务器，不需要登录账号
  - 避免：不说"display:flex+gap Android 不支持"，说"某些手机上会看到奇怪的排版错误，工具自动帮你规避了"
- **预估字数**: 280
- **视觉断点**: GFM Alert `> [!IMPORTANT]` — "预览里是什么样，粘贴进去就是什么样。这是工具的硬纪律，不是口号。"
- **depends_on_previous**: true
- **writer 注意**: 技术原理一句带过或完全不提；讲用户感知到的结果，不讲实现手段

## Section 5: 三步上手，下一篇文章就能用

- **论点**: 不需要部署服务器，不需要申请账号，clone 下来三步完成第一篇排版。
- **引用的 atoms**: atom: action-01, action-02, comparison-01
- **关键细节**:
  - 三步流程（面向无编程背景读者）：
    1. 打开终端，复制粘贴两行命令启动工具（给出完整命令）
    2. 浏览器里粘贴你的 Markdown 草稿，左侧选一个跟文章气质匹配的主题
    3. 点"一键复制"，回公众号后台 Ctrl+V，发布
  - 竞品简对比（3 行，只比最关键的维度）：
    - Markdown Nice：免费，功能稳，但主题同质化；没有 AI 接口
    - doocs/md：功能最全，Stars 最多，也没有 AI 生成主题
    - 壹伴：非技术用户最友好，但付费，AI 只生成文字
    - wechat-typeset：免费开源，AI 做主题，唯一的代价是需要执行两行启动命令
  - 补充：不需要每次都重新启动，本地工具持续运行；草稿自动保存在浏览器，刷新不丢
- **预估字数**: 380
