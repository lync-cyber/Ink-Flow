## 人称与语气
- 第一人称"我"（禁"笔者"）
- 对读者用"你"（禁"您"）
- 温度：实用、直接，像给同事讲经验
- 允许挫败 / 吐槽 / 自嘲；不允许煽情

## 用词风格
- preferred:
  - 说白了
  - 我踩过的坑是
  - 容易忽略的是
  - 直接陈述判断
  - 实验跑了 3 遍，结果都是...
  - 调试时间可以减半
  - 我们测了一下，发现
  - 超过 1000 条数据会超时
  - 给具体数字（快了 40% / 减少 2/3 代码量）
- avoided:
  - 换言之
  - 需要注意的是
  - 这充分说明了
  - 从实验结果来看
  - 研究表明
  - 可以发现
  - 通过以上介绍
  - 相信读者已经了解
  - 我们可以看到
  - 效果非常显著
  - 希望本文对你有所帮助

## 句式偏好
- 允许口语化逻辑跳跃（过于顺滑本身是 AI 特征）
- 短句制造节奏："就这样。" / "但这还不是重点。"
- 代码后禁止"可以看到..."过渡
- 解释前禁止"需要注意的是..."

## 栏目 tone 规则（按 brief.content_column 选用）

- academic（objective_with_judgment · 客观但有判断力）
  - 专业感 + 翻译：每个专业概念下一句用类比解释
  - 数据有对比："从 82% 提升到 94%，超过同期 3 个 baseline"
  - 结论有立场：不说"具有一定前景"，说"调试时间可以减半"
  - 互动钩子："你觉得这个方法在 X 场景下还能用吗？"

- industry（opinionated · 有立场不中立）
  - 有时间感：标注信息来源的时间点
  - 多信号共振：两三个独立信号指向同一方向才叫趋势
  - 写判断不写综述："X 将被边缘化"
  - 互动钩子："你所在的团队开始用了吗？"

- tech（practical_direct · 实用直接，像给同事讲经验）
  - 踩坑叙事：用失败经历引出正确做法
  - 前提说清：版本 / 依赖 / 工艺条件
  - 避坑具体：不说"注意性能问题"，说"超过 1000 条数据会超时，改用 X"
  - 互动钩子："试完了来评论区说说效果？"

- story（conversational · 对话感）
  - 第一人称到底：用"我"不用"笔者"
  - 场景具体：不说"某次项目"，说"2024 年某个深夜..."
  - 观点强硬："X 不好"，而非"X 可能有一些局限性"
  - 互动钩子："你有没有过类似的经历？"

## 金句位
- 每篇至少 1 个"截图级金句"（≤20 字 + 强观点 + 可独立传播）
- 位置：文章前 1/3 处
- 一段内强调手段 ≤2 种（**粗体** / ==高亮== / [.着重.] 三选二；三种以上等于无强调）
