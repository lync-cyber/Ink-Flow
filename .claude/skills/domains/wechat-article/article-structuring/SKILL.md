## 栏目结构骨架

从 `brief.content_column` 读取栏目类型，注入对应骨架作为 outliner 的结构参考。若未指定栏目，使用通用骨架。

---

### 学术前沿（适用：论文解读、研究进展分享）

**核心目标**: 让非该研究方向的技术读者理解"这篇论文证明了什么、为什么重要、工业界能做什么"。

**骨架**:
1. **一句话结论** — 论文的核心发现（不是摘要，是你的判断：这项研究意味着什么改变）
2. **问题背景** — 这个问题之前为什么难？解决它有什么价值？（2-3 段，配图可选）
3. **核心方法** — 方法论要点，用类比代替公式（可配流程图）
4. **关键结果** — 用数据说话，对比 baseline（必配数据图或对比卡）
5. **对工业界的启示** — 落地可能性分析：谁能用、何时用、有什么限制
6. **结论卡** — 3 条核心总结，读者截图分享用

**标题调性**: 提炼核心发现，避免照搬论文标题。好标题示例："{发现} 意味着 {影响}" 或 "{技术} 正在解决 {问题}"

**视觉断点规划**: 方法流程图（section 3）+ 数据对比图（section 4）+ 结论卡（section 6）

---

### 行业趋势（适用：动态分析、趋势判断、政策解读）

**核心目标**: 帮读者在信息噪声中形成判断，而不只是转述信息。

**骨架**:
1. **一句话判断** — 你的核心论断（不是"X 发生了"，是"X 意味着 Y"）
2. **发生了什么** — 事件/数据/信号列举（3-5 段，保持时效性标注）
3. **为什么重要** — 影响链条分析（可配对比卡：此前 vs 此后）
4. **谁会受影响** — 分角色分析：工程师/管理者/供应商/用户（各 1-2 段）
5. **行动建议** — 针对主要读者群体的可操作建议（不泛泛而谈）
6. **结论卡** — 3 条核心总结

**标题调性**: 判断型或冲突型。好标题示例："X 正在发生，{角色} 需要准备了" 或 "X 不会替代 Y，但会淘汰 Z"

**视觉断点规划**: 对比卡（section 3）+ 结论卡（section 6）

---

### 技术专题（适用：实战教程、工具深度、方案解析）

**核心目标**: 读者读完能带走可迁移的设计判断，不只是"知道 X 是什么"。

**骨架**:
1. **一句话结论** — 这个方案解决了什么具体问题（精确到场景，不笼统）
2. **问题定义** — 痛点描述，用失败案例或误区引出（可配误区卡）
3. **方案详解** — 步骤拆解，每步有代码示例或配置片段（可配流程图）
4. **性能验证** — 实测数据或对比 benchmark（必须有具体数字，可配数据图）
5. **避坑要点** — 经验总结，以"我们踩过的坑"或"容易忽略的点"开头
6. **结论卡** — 3 条核心总结

**标题调性**: 实用框架型。好标题示例："X 实战：{解决什么}" 或 "用 X 避开 {具体坑}" 或 "Y 比 X 好在哪"

**视觉断点规划**: 误区卡（section 2）+ 流程图（section 3）+ 结论卡（section 6）

---

### 人物故事（适用：经验分享、人物访谈、思考复盘、观点输出）

**核心目标**: 让读者产生共鸣，觉得"说的就是我"，并拿走 1 个可以立刻改变行为的观点。

**骨架**:
1. **一句话核心观点** — 你的判断，带立场（不要"其实有时候可能..."这类软化表达）
2. **故事/场景** — 具体事件，用叙事语气（时间+场景+转折），不超过 3 段
3. **反思与分析** — 为什么会这样？是认知缺陷还是环境问题（可配误区卡）
4. **我现在怎么做** — 改进方案，要具体到行为层面（不是"要重视 X"）
5. **给同行的建议** — 泛化到读者场景的建议，用第二人称
6. **结论卡** — 3 条核心总结

**标题调性**: 第一人称、对话感。好标题示例："我为什么放弃了 X" 或 "做了 N 年 {领域}，才明白 Y"

**视觉断点规划**: 金句卡（section 1 或 3）+ 误区卡（section 3）+ 结论卡（section 6）

---

## 通用骨架（无栏目时使用）

1. **核心论点** — 一句话总结文章价值
2. **背景** — 问题的来源和重要性
3. **主体** — 论证展开（2-4 节，按 outline 章节划分）
4. **结论** — 可操作的总结

---

## 注入规则

- 读取 `articles/{slug}/brief.md` 的 `content_column` 字段
- 将对应栏目骨架作为 **结构建议** 注入 outliner 的 Context 段
- outliner 可根据具体内容调整 section 数量，但需保持骨架的核心逻辑顺序
- 结论卡（文末 3 条总结）在所有栏目中均为必须项
