## 一、正向替换规则

> 禁用词的确定性检测由 `lint-config.yaml` 定义、`lint.py` 执行。
> 本表提供正向替换建议，与 quality-redline 的句式禁用互补（redline 说"禁止什么"，本表说"改成什么"）。

| 换掉 | 换成 |
|------|------|
| "换言之" | "说白了" |
| "需要注意的是" | "我踩过的坑是" / "容易忽略的是" |
| "这充分说明了" | 直接陈述判断 |
| "从实验结果来看" | "实验跑了 3 遍，结果都是..." |
| "研究表明" | "{研究者}发现" / "我们测了一下，发现" |
| "可以发现" | 直接说发现了什么 |
| "通过以上介绍" | 删掉，直接到下一段 |
| "相信读者已经了解" | 删掉，直接说 |
| "我们可以看到" | 直接描述看到的 |
| "效果非常显著" | 给具体数字: "快了 40%" / "减少了 2/3 的代码量" |

## 二、栏目语气指南

### 学术前沿
- 专业感 + 翻译: 每个专业概念下一句用类比解释
- 数据有对比: "从 82% 提升到 94%，超过同期 3 个 baseline"
- 结论有立场: 不说"具有一定前景"，说"调试时间可以减半"
- 语气: 客观但有判断力

### 行业趋势
- 有时间感: 标注信息来源的时间点
- 多信号共振: 两三个独立信号指向同一方向才叫趋势
- 写判断不写综述: "X 将被边缘化"，非"X 面临一定挑战"
- 语气: 有立场、不中立

### 技术专题
- 踩坑叙事: 用失败经历引出正确做法
- 代码完整: 说清前提（版本、依赖、环境）
- 避坑具体: 不说"注意性能问题"，说"超过 1000 条数据会超时，改用 X"
- 语气: 实用、直接，像给同事讲经验

### 人物故事
- 第一人称到底: 用"我"不用"笔者"
- 场景具体: 不说"某次项目"，说"2024 年某个深夜..."
- 观点强硬: "X 不好"，而非"X 可能有一些局限性"
- 语气: 对话感，像给有经验的朋友聊天

## 三、人味技巧

### 节奏打破
- 允许适度逻辑跳跃和口语化（过于顺滑本身是 AI 特征）
- 偶尔短句制造节奏: "就这样。" / "但这还不是重点。"

### 主观标记
- 每篇至少 1 处个人经验/观点（标记为 `<!-- USER_FILL: {提示} -->`）
- 允许偶尔口语感叹（"这就离谱"、"坑就在这"）
- 适当反问句增加互动感

### 认知翻转写法
- "X 不是 A，而是 B"制造认知反差
- 先误区后正解
- "大多数人会..."引出对比，不过度使用

## 四、互动设计

### 栏目 CTA 推荐

| 栏目 | 推荐 CTA | 正文互动钩子 |
|------|---------|------------|
| 学术前沿 | 收藏/在看 | "你觉得这个方法在 X 场景下还能用吗？" |
| 行业趋势 | 分享/讨论 | "你所在的团队开始用了吗？" |
| 技术专题 | 收藏/实操 | "试完了来评论区说说效果？" |
| 人物故事 | 评论/共鸣 | "你有没有过类似的经历？" |

### 互动钩子位置
- **正文 60% 处**: 插入开放式问题，打断单向阅读
- **结尾前一段**: 强观点或反问句制造讨论欲
- **文末 CTA**: 根据 brief.cta_type 生成引导语

### 金句设计
- 每篇至少 1 个"截图级金句"（≤ 20 字 + 强观点 + 可独立传播）
- 位置: 文章前 1/3 处
- 可配合金句卡 SVG 组件使用

## 快速自检清单

- [ ] 开头非定义句/背景句/流水账
- [ ] 无"首先...其次...最后..."（至多 1 处例外）
- [ ] 结尾非展望套话或号召套话
- [ ] 术语首次出现有解释
- [ ] 每 section 有具体数字或代码
- [ ] 每 section 有个人语气
- [ ] 至少 1 个互动钩子
