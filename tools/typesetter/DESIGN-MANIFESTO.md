# InkFlow × doocs/md 设计立场

> 此文档是 InkFlow 覆盖层主题的"宪章"。新增或修改 `overlay/theme-css/*.css`
> 必须对照本文；`.design-guard.yaml` 是可机器校验的子集。

## 一、为什么需要显式立场

2026 年，AI 生成的视觉模板占据了内容平台的大多数页面。它们通常共享同一组"配方"：

- 大面积渐变紫 / 蓝（AI 默认配色）
- 玻璃拟态（backdrop-filter: blur）滥用
- 发光边框 / 霓虹描边
- 过度圆角卡片（≥ 24px）+ 多层阴影堆叠
- "科技感"但信息密度极低

它们的问题不是不好看，而是**让读者一眼认出"这是 AI 模板"**，从而对内容失去信任。
公众号作者需要的视觉资产必须反过来：**让读者觉得"这是一个真实的人在长期维护的专栏"**。

## 二、核心主张

### 2.1 工具服务于作者身份，不服务于 AI 模板工厂

- 每个栏目必须有**可识别的编辑部身份**（学术 / 行业 / 技术 / 故事）
- 不追求"通用美观"，追求"这个专栏的主编一眼就能认出"
- 拒绝把 4 个栏目做成"换色版本"

### 2.2 编辑质感 = 线 + 字距 + 留白

**不**用来营造质感的：
- 阴影堆叠（多层 box-shadow）
- 大圆角（≥ 24px border-radius）
- 玻璃拟态（backdrop-filter）
- 霓虹描边（0 0 Npx 发光色）
- 渐变填充（linear-gradient 作为 H1/H2/按钮底色）

**用来**营造质感的：
- 细实线（1–2px border）
- 字距（letter-spacing 承担层级标记）
- 留白（section-gap / paragraph-gap）
- 字号阶梯严格三档（body / h3 / h2），不做花哨过渡

### 2.3 出版物锚点优先

每个栏目的头部必须承载"出版物身份"信号：期号、日期、作者。这让读者第一眼识别
"这是某专栏的第 N 期"，而不是"一篇被模板化的文章"。

（此项由上游 doocs/md 的 CodeMirror 编辑器负责，本覆盖层只保证 CSS 留出对应位置。）

### 2.4 色板约束

- **饱和度 ≤ 60%**：饱和色让人想到 AI banner，不像编辑部
- **亮度差承担主要层级**：同色系内用明度，不用色相跳变
- **每栏目一主一辅**：不堆配色（主色 + accent 即可）
- **禁用色相**：纯紫（#8B5CF6 族）、霓虹青（#00FFFF 族）、AI 渐变蓝（#4F46E5→#7C3AED）

### 2.5 可读性优先于装饰

- 正文行高 **1.70–2.00**
- 正文字号 **14–16px**（移动端计算后约等）
- 两端对齐只在"叙事"栏目（story）启用；其他栏目左对齐以保留节奏锚点
- 段落字符数 ≤ 120（移动端单屏高度约束）

## 三、禁令清单（可机器校验）

详见 `.design-guard.yaml`。`scripts/design-guard.mjs` 会扫描 `overlay/theme-css/*.css`
并对命中的正则报错。

| 模式 | 原因 |
|---|---|
| `linear-gradient([^)]*violet\|purple\|indigo)` | AI 紫蓝渐变 |
| `backdrop-filter\s*:\s*blur` | 玻璃拟态 |
| `box-shadow\s*:[^,;]+,[^,;]+,[^,;]+` | 多层堆叠阴影 |
| `box-shadow\s*:\s*0\s+0\s+\d+px` | 霓虹发光 |
| `border-radius\s*:\s*(2[4-9]\|[3-9]\d)px` | 过度圆角 |
| `animation\s*:` / `@keyframes` | 动画（微信会剥离，且强化"模板感"） |

## 四、四栏目视觉定位（简表）

| 栏目 | 关键词 | 主色 | 字体 | 对齐 | 层级装饰 |
|---|---|---|---|---|---|
| ink-academic（学术前沿） | 期刊 · 严谨 · 靛蓝 · 赭石 | #1B3A5C | sans | 左 + 正文 justify | H1/H2 底线 + H3 竖条 |
| ink-industry（行业趋势） | 简报 · 节奏 · 松石 · 琥珀 | #1A3B4A | sans | 左 | H2 细描边 inline pill + H3 竖条 |
| ink-tech（技术专题） | 工程 · 信息密度 · 午夜 · 暗绿 | #0C1F37 | mono | 左 | H2 竖条 + H3 `›` 前缀 + H4 `//` 前缀 |
| ink-story（人物故事） | 叙事 · 温度 · 赭棕 · 衬线 | #563322 | serif | 居中 + 正文 justify | H2 居中 + `— · —` 装饰行 + H3 斜体居中 |

## 五、何时允许突破立场

本文档是"默认立场"，不是铁律。在以下情况可以妥协，但必须在 PR 里显式说明：

1. 平台机制限制（如微信公众号会剥离某 CSS，不得不降级到别的方案）
2. 读者反馈长期 aggregate 显示某处影响阅读（比如行高需从 1.75 调到 1.9）
3. 新增第 5 栏目时需要一种"不同形态" —— 这时扩展本文，不删除现有约束

新增栏目的 PR 必须：
- 回答"这个栏目的主编是谁、长什么样"
- 说明它和现有 4 栏目的**视觉差异化**（不是"又一个换色"）
- 通过 `node scripts/design-guard.mjs`
